# UX監査 パソパソ側メモ（v0.1.0・独立審査と照合前）

対象：MainActivity.kt / LevelSystem.kt / Questions.kt / ProgressStore.kt、設計 v1.1、ART_DIRECTION v1.0
方法：コード読みによる監査。実画面・人間の体験確認は未実施（未確認として残す）。

## 自分で見つけた指摘（重大度順）

### A-1レベルアップの山場が「結果画面まで遅れる」＋クイズ中にバーが無い
設計の核は「回答直後にバーがその場で伸びる」。実装はクイズ画面にバーもXP表示もなく、正解しても数字の変化が見えない。レベルアップに気づくのは5問終わった結果画面だけ。日常の小さな手応え（正解）と山場（レベルアップ）の接続が切れている（experience-balance：伝える順序と山場の配分）。

### A-2セッションが簡単に壊れる
- セッション中も下部タブが生きていて、タップするとセッションが黙って破棄される（解いた分のXPは保存済みなのに「今日の分は完了」にならない中途半端な状態）。
- 画面回転・Activity再生成でセッション位置が消え、ホームに戻る。
- 戻るボタンへの配慮なし。

### A-3復習タブに「今日の復習」を始める手段がない
復習タブは「今日の復習○問」と数を出すのに、始められるのは「苦手だけ5問」だけ。期限が来た復習を直接消化する導線がなく、ホームの「今日の5問」に混ざるのを待つしかない。出した情報に対応する操作がない（到達確認の失敗）。

### A-4金の使い方が方針から逸脱
ART_DIRECTIONで金は「レベルアップの瞬間だけの封印色」。実装は結果画面の「+XP」表示に常時金を使い、山場の特別感を薄めている。さらに金文字 #C9A227 は生成り背景に対してコントラスト約2.2:1で、補助文字としての 4.5:1 に届かない。

### A-5ホームの統計行が3指標を1行に詰めている
「解いた問題○・卒業○問・今日の復習○問」は Bランク情報。主役（レベル）の下で小さく出すのは良いが、1行に3つ詰めると読ませる。復習数は復習タブと重複もしている。

### A-6バーの0%表現と進捗の嘘
levelBar は進捗0でも最小幅1ウェイトで塗りが出る（0%なのに少し進んで見える）。正確さの問題。

### A-7カテゴリ画面に開発者向け文言
「プロトタイプ版は各4問・全20問。本番はP0で約600問」という内部事情の説明がユーザー画面に出ている。minimal原則では Cランク（利用者には不要）。進み具合も数字テキストのみで、設計の「ミニバーで量だけ示す」になっていない。

### A-8動きが設計どおりでない
方針は「バーが伸びる／カードがめくれる」アニメーション。実装はどちらも即時表示（カードは表示/非表示の切替）。動きを減らす設定への追随も未実装。山場の弱さ（A-1）と同根。

### A-9初回体験がない
初回起動でいきなりホーム（Lv.1）。「何のアプリか」「目指せ100」「1日5問」の3点が伝わる前に始まる。mobile_onboarding の観点では、最初の小さな成功（最初の5問でレベルアップ寸前まで行く体験）への接続設計が未実装。プロトタイプ範囲外ではあるが、本実装前に設計が必要。

### A-10細部
- 文字サイズが 12/13/14/15/16/17/18/20/22/24/26/30/72 と多段すぎる（方針は3〜4段）。
- 正解/不正解の区別が色中心（紺/グレー）。フィードバック文で補えているが、ボタン側にも ○/△ 等の形の差があると色覚に依存しない。
- 「あと正解約○問」は復習正解（5XP）を混ぜると実際はもっとかかる場合がある（目安表記としては許容範囲だが、表現は「あと約○問分」等が正確）。
- おかわりセッションでも結果文が「今日の分は完了」のまま。
- 卒業した問題も補充枠で普通に出題される（設計の「たまに抜き打ち」と整合はするが、卒業の意味が弱い）。

## 残すべき良さ
- ホームの主役は明確（Lv数字が最大、ボタン1つ、下部タブ3つ）。
- 間違いを赤で責めない（グレー表示＋正解提示）方針が守れている。
- 全問に解説＋場面＋出典が出る（アプリの価値の中心が成立）。
- レベルが下がらない・煽り通知なし・権限ゼロはコンセプトどおり。
